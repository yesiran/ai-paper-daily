01

故事

主角是一段正在被逐层加工的当前文字。标准 Transformer 把一个 token 变成向量，沿网络层不断修改，同时读取以前留下的键和值缓存。这里的困境很具体：历史记录可以被读取，但每个新 token 的主通路从自己的嵌入重新开始。作者于是追问，每个指定层能否带着自己的持续状态，进入下一次计算？这不是宣称原模型没有记忆，而是寻找另一种使用历史的结构。论文 §3.1

旧路包括加宽、加深、增加推理步骤与改善跨层连接。转折是把一部分容量分给跨 token 的横向状态。解法分两步：先结合该层旧状态和当前输入更新向量，再用它调节注意力读写及前馈计算。为了训练时仍能并行处理多个位置，基础更新对旧状态只做输入决定的缩放与相加；更丰富的非线性交互放在读出等路径上。横向状态存在于中间 Lattice 层，而不是无差别加到整个网络。论文 §3.2

结局有成功，也有边界。200亿 token 训练后，相近参数和前向计算量的模型把验证困惑度从15.410降至14.400；但更强的顶部反馈要额外计算，主通路压得过窄也会损失质量。故事的内核因此是一个可检验的容量分配问题：在当前 token 的即时加工与跨 token 的持续状态之间，怎样分配预算更有效？论文给出了若干有效配置，没有给出普适最优比例。论文表1、§4.4

02

脉络

从结果往回读，第一层问题是：收益来自新增的时间通路，还是仅仅来自更好的跨层传递？作者把 Lattice 与超连接、输入残差等方式组合。超连接加输入残差的验证困惑度为14.22，加入 Lattice 后降至13.61。它支持二者在测试设置中有互补性。Hyper-Connections 的研究对象正是不同深度特征之间的连接关系；LLLM 由此把问题扩展到同一层跨 token 的延续。LLLM §4.2 Hyper-Connections

第二层问题是：循环状态怎样兼顾内容选择与训练并行性？Mamba 提供了输入相关的选择性状态更新和并行计算前驱。LLLM 使用类似的可扫描更新，但在 Transformer 实现中保留注意力，让新增状态影响查询、缓存写入和前馈加工。Mamba LLLM §3.2

继续回到当前论文，多循环骨干实验把两条线接到一起：即便骨干已经有循环记忆，添加横向状态后仍能改善困惑度。这与“记忆如何被控制也有价值”的解释一致。需要避免的历史叙事是把前驱排成一条必然通向 LLLM 的道路；它们处理的是相关但不同的问题。本文的原创判断是，层间传递、序列存储和持续状态对计算的调节，可以作为三个不同的预算与评估对象；论文还没有证明三者之间存在统一缩放规律。论文 §4.3—§5

03

本质

最小机制可以用一次处理过程说明。当前 token 到达某个 Lattice 层时，模型先取得下方传来的主通路向量，再据此算出保留系数和候选写入内容；它们与该层上一次的横向状态结合，得到这一次状态。随后，新状态调节查询、键和值的特征缩放与偏移，并影响前馈模块。因此，同样是保存过去，横向状态同时参与决定当前怎样读取、写入和变换信息。论文 §3.2

可并行训练的关键条件，是给定该层输入后，保留系数和写入项不直接依赖尚未算出的旧横向状态。多个“缩放再相加”的变换可以组合起来，通过并行扫描求得各位置结果。这个限制也解释了为什么顶部反馈需要另行处理：低层更新若依赖上一 token 的高层状态，就跨越了原有的深度计算顺序。论文用多轮 Jacobi 扫描近似这种反馈，增加了计算，也出现与顺序展开不同的质量。论文 §3.2.2、附录 A.2.3

这一机制能把两项不同观察联系起来：与超连接叠加有效，符合“跨时间延续与跨深度传递作用不同”的解释；已有循环记忆的骨干仍获益，符合“状态还在调节记忆使用”的解释。它们支持机制的合理性，却未排除所有其他解释。不可再省的判断是：活动状态要有持续路径，也要有影响当前计算的接口；仅有一个更大的向量，不能保证有效。极窄主通路的失败正是后一句的实验提醒。论文 §4.2—§4.4

04

思辨

支持这篇论文的理由，是作者没有只拿新架构与一个较小基线比较。主实验包含近似等参数和计算量对照，另有更宽、更深的 Transformer、多个循环骨干、残差结构组合以及部件消融。基础 LLLM 的九项零样本任务平均准确率也从45.46%升至47.67%，使收益不局限于一个验证困惑度。证据覆盖了几种不同问题，但仍属于论文作者报告的结果，不等于已经独立复现。论文 §4、表4

反对过度外推的第一条证据来自成本：三轮反馈版本的最佳分数对应更高前向计算；改为低成本顺序展开后，质量下降。第二条来自失败：把主通路压到256维，配上768维横向状态，基础版本仍差于512维 Transformer。容量并不能任意搬移。第三条是评估协议：循环骨干的下游结果在若干耦合配置中按任务平均分选择最佳者，阅读结果时应保留这一选择条件。论文表1、§4.3—§4.4

最容易误用的反例，是把固定大小横向状态说成整个 Transformer 恒定内存；原有缓存仍然存在。另一个误用，是看到记忆方向更集中，就认定有效信息更多或因果机制已经查明。作者的几何分析支持一种解释，没有单独完成因果归因。长程智能体、跨会话保留、数十亿以上模型规模的收益，在本文主要实验中都没有得到建立。合理的产品推演应先变成新的评估问题，而不是直接变成能力承诺。论文 §3、§4.4、附录 A.4

05

自测

问1：标准 Transformer 已有历史缓存，论文还要增加什么？
答：增加指定层自己的跨 token 活动状态。缓存保存以前写下的键和值，新状态则持续更新并介入当前读写与计算。二者不能混称为同一种记忆。论文 §3.1—§3.2

问2：一次新的计算中，横向状态先做什么？
答：结合该层旧状态和当前层输入更新；再调节查询、键、值与前馈模块。它不是等输出完成后才追加的一段摘要。论文 §3.2

问3：有时间递推，为什么还能并行训练？
答：给定层输入后，基础更新对旧状态是仿射变换，其系数不直接由旧横向状态生成，因此可以组合并行扫描；各层仍按深度顺序执行。论文 §3.2.2

问4：哪组结果最适合判断容量分配是否有效？
答：先看约4.06亿参数、200亿训练 token 的单次扫描对照：困惑度15.410降至14.400，估算前向计算量0.71变为0.72 GFLOP/token。它比跨预算拼接最佳分数更有解释力。论文表1

问5：能否给三轮反馈版本同时标注最佳质量和最低推理成本？
答：不能。三轮扫描为14.026困惑度、1.85 GFLOP/token；同一检查点顺序展开约为0.72 GFLOP/token，但困惑度变为14.733。论文表1

问6：反正横向状态有效，是否应尽量缩小主通路？
答：论文反例是否定的。256维主通路配768维横向状态的基础版本为19.58困惑度，差于512维 Transformer 的18.87；两种容量的比例仍然重要。论文 §4.4

问7：它是否已经证明长程智能体更可靠？
答：没有。主实验是2048 token上下文下的语言建模及下游任务。把持续状态用于长程任务是研究推演，必须另做能力与成本评估，不能由困惑度直接推出。论文表1、附录 A.4
